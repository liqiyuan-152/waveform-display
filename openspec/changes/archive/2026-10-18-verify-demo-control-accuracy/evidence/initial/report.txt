波形控制项验收计划与首轮测试报告
日期：2026-10-18

目标
逐项验证左侧输入能精确控制右侧 SVG，而不是只检查表单数值。
完整计划见 checklist.json，共 177 个条目。条目是验收任务，不是 177 项已通过。
执行顺序：布局 → 边框 → 线条/数据点 → X/左右值轴 → 网格/零线 → 文字/图例/空状态 → 单曲线覆盖 → 动画/数据切换。

每项验收方法
1. 记录原值、显示条件和单曲线覆盖情况。
2. 一次只修改一个字段，检查 SVG 的属性、文本、路径、刻度或坐标轴绑定。
3. 检查正常值、边界值、清空、非法值，以及恢复原值后的行为。
4. 下拉菜单逐个候选值检查；左右值轴和每条曲线分别检查。
5. 条件项先打开对应显示开关；零线使用跨零的数据域。
6. 动画分别验证时间过程与结束态，不把结束态通过当作时间精度通过。
7. 记录输入、期望、实际、截图/断言和通过/失败/待测状态。

问题 C-01：重新跟随全局导致曲线样式丢失
优先级：高。
复现：原始数据 → 线点/线条 → 全局线宽设为 4.5、透明度设为 0.35 → 曲线 → 第一条曲线勾选“颜色跟随全局”和“线宽跟随全局”。
期望：第一条路径保留全局颜色 #2563eb 和全局线宽 4.5，其他曲线不变。
实际：第一条路径 stroke 和 stroke-width 属性均被删除；曲线可能消失，图例仍显示颜色。
证据：inheritance-bug.jpg；浏览器 SVG 属性读取；新增预期失败测试。
定位：src/renderer/series.ts 的样式对象展开会让 style 中的 undefined 覆盖全局默认值；SeriesForm 使用 undefined 表示恢复继承。
建议任务：统一处理继承字段，验证全部线条和数据点字段的“自定义 → 跟随全局 → 再次改变全局”全过程。

问题 C-02：线宽为 0 时图例与曲线不一致
优先级：中。
复现：全局线宽设为 4.5 → 曲线 → 第一条曲线取消“线宽跟随全局” → 线宽设为 0。
期望：曲线和图例均反映线宽 0。
实际：曲线 stroke-width="0"，图例 stroke-width="4.5"。
定位：src/renderer/legend.ts 使用逻辑或读取 lineWidth，将有效值 0 当成缺省值。
建议任务：保留有效零值，补查零线宽在图例、导出和更新中的一致性。

正常但容易误解的行为
原始四条曲线都设置了单独颜色和线宽 1.5；因此修改全局颜色/线宽不会直接覆盖它们。这个覆盖优先级正常，但当前“返回继承”存在 C-01。
原始数据的值域没有跨零，零线不出现正常；值轴范围设置为 -10～10 后，零线样式可正常控制。
设置 X/Y 网格宽度后，它们覆盖公共辅助线宽度；这是正常的局部覆盖。
SVG 根节点 width 保持 100%；固定宽度通过 viewBox 体现。本轮使用 viewBox 验证内部坐标尺寸，没有将其等同于屏幕物理像素宽度。
